# 새 He pair-support 단위: 연구 위치와 완료 계약

현재 PR112는 완료·봉인된 선행 단위다. 사용자가 이어지는 전수 조사와 다음 이론·코딩 루프를 새로 요청했으므로, `CONTRACT.json`에 별도 단위 `CR_PHYS02_HE_PAIR_SUPPORT_V1`과 독립 40 CPU-s를 고정했다. 이전 잔여 예산은 이월하지 않는다.

조사에서 관찰한 최신 CR은 여전히 PR112다. 중앙은 REC의 새 반환을 포함한 `df806909…`이며, qualified **28/88**, DAG **88 nodes / 17 edges**다. 서로 다른 owner의 scoped 완료 숫자를 더하지 않는다. 최신 REI C8과 REC recovery 본문을 오래된 백업/PR 설명보다 우선하며, 실제 CR same-source exclusive He 입력을 확보했다고 주장하지 않는다. 정확한 조사 범위와 접근 공백은 `intake/REPOSITORY_SURVEY.json`, `BACKUP_AND_DIALOGUE_SURVEY.json`, `SEARCH_COVERAGE.json`에 있다.

이번 질문은 주어진 네 birth-bin graph가 허용하는 cross-double mass의 정확한 구간과 이를 실제 저장된 atomic marginal에 올리는 구성이다. Graph가 물리적으로 관측되었다는 전제는 없다. 완전 graph는 PR112의 bound로 환원되어야 하고, 제한 graph는 해당 명시적 가정 아래에서 더 좁은 bound를 준다. Source normalization, 상태, proper history, RR와 photon port는 기존 byte identity를 재사용한다.

R1 계약 → R2 근거 대응 → R3 명제/전제 → R4 표현 선택 → R5 구성적 증명 → R6 독립 검토 → R7 bounded CAS 판별 → R8 판정 → R9 구현 계약 → R10 이론 인계 순으로 수행한다. 이어 C1 baseline → C2 식/데이터 mapping → C3 exact algorithm → C4 자원 admission → C5 구현 → C6 계약/회귀 → C7 독립 과학 검증 → C8 정확도/재현/figure → C9 독립 검토 → C10 전달을 수행한다.

각 단계는 실제 Git commit과 두 provider R2 확인 후에만 완료 수로 표시한다. SOURCE/CLOSEOUT은 한 번 봉인하며 실제 원본 full GET·전체 SHA·모든 payload SHA/CRC를 확인한다. 뒤늦은 영수증을 넣기 위해 재생성하지 않는다. 단위 종료 후 추가 science allowance는 0이며 다음 노드는 자동 실행하지 않는다.
