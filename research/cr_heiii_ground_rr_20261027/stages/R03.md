# R3 — 주장·가정·전제의 정렬

## 채택한 물리 문제

채널은 He4III + tagged fast electron → He4II(1s) + spontaneous photon이다.
Native HeII PI의 문턱 54.42 eV와 모든 적합계수, Emax 50000 eV를 함께 쓴다.
g_bound=2, g_ion=1, d=1이며 target density는 n_HeIII=0.01 cm⁻³다.
기존 T=10000 K, ne=0.14 cm⁻³, lnΛ=20, H/He 조성과 세 저장 z를 보존한다.
Elemental He→He4는 조건부 대응, 표적은 정지한 무거운 입자, 반동은 0이다.
Nonrelativistic electron 모델을 소비 격자의 실제 에너지에서 해석한다.
source의 50 keV 상한을 전체 수송의 정확도 인증으로 읽지 않는다.

## 근거 종류별 판정

| 주장 | 근거 종류 | 이번 적용 |
|---|---|---|
| HeII PI row와 Milne 관계 | 원전·고정 source bytes | R2에서 확인한 동일 식·행 |
| d=1 | NIST ground J와 bare electronic state count의 직접 적용 | 전자 spin 중복 없음 |
| n_HeIII=.01, fixed bath | 기존 project 입력 | 새 문헌 측정값이 아님 |
| K0=stored PR106 HeI matrix | 정확한 수치 baseline 정의 | 과거 HeI addition loss는 상속 |
| 양성성·경쟁·response bound | R5에서 유도할 유한 행렬 명제 | invertible killed M-matrix 조건 |
| 새 capture 확률·시간·에너지 | 아직 미실행 | C7/C8 실제 결과 이후 판정 |
| native 25-state event map | source 변수 정의와 보존식 | source-only algebra, 새 IVP 없음 |

## 세 가지 수학적 객체

1. 이상적인 이전 해 h0=K0⁻¹b.
2. 저장된 이전 열 hhat0. 그 잔차는 r0=b−K0 hhat0다.
3. 구현할 안정 응답 δhat=−K1⁻¹D hhat0, K1=K0+D.

δhat는 저장 열에 대한 정확히 정의된 새 선형 문제다. h1−hhat0에는
K1⁻¹r0가 더 있으므로, 이를 모든 자릿수에서 동일한 값으로 선언하지 않는다.
이상적 변화 δ*=−K1⁻¹D h0와의 관계도 R5에서 유도한다. 기존 검증의
own-column 기준은 유지하고, 직접 subtraction은 진단으로만 둔다.

## 사건과 시간의 단위

원 pulse source와 종료까지의 capture probability를 곱한 결과는 적분 사건수
cm⁻³다. 새 export의 SI 변환은 m⁻³이며, integrated energy는 J m⁻³다.
rate와 exposure는 제공되지 않았으므로 null이다. 기존 rate-only Event API에
1초를 암묵적으로 넣지 않는다. 25좌표 projection에 nb를 제공할 때만
a=Ncap/nb와 J/baryon의 수치값을 계산한다.

He4III index12→He4II index11, fast-electron count −1, retained photon +1이다.
기존 w_ext는 external photon-transfer ledger이므로 Δw_ext=0을 유지하고
retained-photon count/energy를 별도 반환한다. Δthermal number=0, 이 RR 사건의
Qthermal=0이며 전체 stopping/heating에는 여전히 필요한 공급자가 남는다.

## 실행과 채택 경계

고정된 과학 기준: backward residual 2e−12, partition/total energy 2e−8,
probability 2e−10, rare bound/independent own-column 5e−10, event energy 5e−13.
ordinary grid .005, paired-response grid .01, upper-domain 1e−5를 유지한다.
검사 실패를 통과시키기 위해 기준을 완화하지 않는다. 독립 계수 비교는 5e−13.
모든 신규 실행과 실패는 새 30 CPU-s 단위에 기록한다. 과거 승인·잔여 예산을
가져오지 않는다. native thread1, worker address-space512 MiB, reserve1 GiB.

R3 COMPLETE_SCOPED. 중앙 27/88, 별도 개발 32/88, 이번 소비자 0/1.
새 strong no-go를 제안하지 않으므로 NG1–NG7 신규 채택 대상은 없다.
