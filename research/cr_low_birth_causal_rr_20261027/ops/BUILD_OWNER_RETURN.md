# Actual owner-return metadata assembler

build_owner_return.py assembles the root's final owner return and the six-role
results input consumed by build_central_low_birth.py. It has been authored and
statically read only. The author has not run, imported or compiled it, and no final
return, results manifest or central candidate has been generated by this task.

The assembler reads JSON metadata and the two metadata-helper source files.
It does not import production/reference science, open an NPZ/ZIP payload, glob
directories, query a provider, invoke Git, create an archive or publish anything.
The central validator is loaded only after its independently reviewed exact
SHA256 30680efa19450e9a0afc0186321c34bbc35b3771380792aa30eaac1779683fca
is verified. The validator's current strict PASS_SCOPED review gate is unchanged.

## Required actual inputs

All of these are required CLI arguments:

| Argument | Actual input |
|---|---|
| --primary | Saved primary RESULT.json |
| --controls | Aggregate evidence/C06_ACCEPTANCE.json |
| --independent | Successful independent reference RESULT.json |
| --final-review | Actual final review/C9_FINAL.json |
| --budget | Active unit EXECUTION_BUDGET.json |
| --ledger | Actual final evidence/EXECUTION_LEDGER.json |
| --source-r3 | Actual canonical-source Dropbox/Drive full-GET R3 receipt |
| --central-count-baseline | Actual independently qualified current-count input |
| --dag | Exact current central DAG bound by that count input |
| --stage-receipts | Explicit twenty-file stage-receipt pin manifest described below |
| --science-sha, --documents-sha | Actual lowercase40-hex S and D |
| --central-head | Actual current central HEAD |
| --pull-request | Actual bass_cr PR URL |
| --out-owner-return, --out-results, --receipt | Three distinct new output JSON paths |

The six primary/result/review/budget files must reside within this exact unit.
The stage receipt manifest and C10 postpublication receipt may be outside the
repository because that final receipt is created after D. The caller supplies
those explicit files; the assembler never searches for the latest matching file.

Default review JSON pointers are /verdict, /blocking_findings and
/open_blocking_findings. CLI overrides are available through
--review-verdict-pointer, --review-blocking-pointer and
--review-open-blocking-pointer. The actual verdict must satisfy the unchanged
central validator, the actual blocker count/list must be empty and the separate
open-blocker array must be empty. HOLD/FAIL is refused. No future review decision
is assumed.

The final review's reviewed_files must contain exact path/bytes/SHA256 pins for
the current primary, aggregate controls, independent result, active budget and
final ledger. Paths may be unit-relative, repository-relative or absolute within
the unit. Its actual scientific_scope and runtime_limits objects are preserved
in the owner return.

Evidence descriptors default to the supplied actual S. Use repeatable
--evidence-revision ROLE=D for any evidence that is actually first contained at
D. Roles are primary, controls, independent, execution_ledger, execution_budget
and final_review; ROLE=S is also accepted. These are root's explicit revision
assignments, not a claim that the offline assembler queried Git or checked remote
blob membership.

## Actual stage-receipt pin manifest

The manifest has schema CR_LOW_BIRTH_OWNER_RETURN_STAGE_INPUT_V1,
unit CR_PHYS02_LOW_BIRTH_CAUSAL_RR_V1, and stages, an explicit list containing
exactly R01–R10 and C01–C10. Each row supplies:

| Field | Meaning |
|---|---|
| stage | One actual stage ID |
| local_path | Absolute regular JSON receipt file |
| bytes | Exact positive byte count |
| sha256 | Exact SHA256 of the receipt |

Every receipt must have the actual stage-publication schema, a non-force Git
acknowledgement, exact commit/tree/expected-parent identities and consistent
stage numbering. The twenty commits must be distinct and form their recorded
publication ancestry chain. Actual S must occur in that chain; actual D is its
last commit.

Both Dropbox and Drive must have actual acknowledged R2-or-R3 records with
matching archive sizes and explicit IDs. Archive name/hash/member metadata is
validated without reopening archives. The workflow completion and dual-backup
count are derived from these validated receipts. Earlier stage27/88 observations
remain as published; they are not replaced with the current baseline count.

## Failure history, numerical limits and exact bindings

The assembler reuses the central validator for same-unit preparation costs,
the failure-inclusive separate40 CPU ledger, scoped gates, native25 scope,
canonical source R3 and current authoritative central count. It never embeds a
future CPU total, reference check count, final archive identity or central M.

The aggregate C6 controls are additionally traced to each actual raw result.
Their accepted names are unique, each selected check actually passed in its
pinned source, reuse/repair and evaluation counts are reconstructed from saved
metadata, and the targeted repair must have the selected-one-control scope.
The original controls_v1 failed result and receipt, controls_v2 receipt, diagnosis
review and retained preparation metadata are all read through exact saved pins.
Their failure/recovery costs remain in the canonical cumulative debit ledger.
None of the controls or preparations is rerun.

The independent result must bind the exact primary result and saved array SHA,
and its recorded comparison list must agree with its actual check count. Arrays
are not opened or recomputed. The original primary's pending-reference label is
preserved alongside the later independent result and actual C9 decision.

The return copies saved primary tail records, preparation weight diagnostics and
the independent review's limits. A positive exact-arithmetic tail can underflow
when represented as binary64; a serialized zero is not an exact-zero remainder
or outward-interval certificate. No continuous-energy or global physical error
bound is created. Caloric accounting is not promoted to physical heating, and
retained photons remain separate from w_ext/heating.

Per-attempt monitor observations and terminal CPU debits are both preserved.
Zero procfs samples do not imply zero worker cost or a preventive aggregate hard
cap. Memory admission remains a policy estimate. Failed plot/control attempts
remain in the current final ledger; the assembler does not assume that the last
observed intermediate ledger is final.

The legacy ledger field named measured_worker_plus_coordinator_cpu_s includes
the charged preparation baseline and its conservative tail. It is copied only as
legacy_ledger_measured_worker_plus_coordinator_cpu_s_as_saved with an explicit
note that this is not pure measured CPU. The actual final closeout's separation
of measured CPU, conservative tails and total charge is preserved through the
independent C9 runtime_limits.budget object and its exact closeout pin. Those
values are read from the actual review rather than embedded in this helper.

## Outputs and subsequent publication

All checks precede output creation. The assembler invokes the existing central
owner-return validator on the in-memory result before writing. It then writes
the results input, owner return and assembly receipt with exclusive creation,
performs full byte readback, and rechecks all inputs for concurrent changes.
JSON numbers use the central helper's Decimal parser/serializer.

central_commit_M remains null. The current central completed count comes from
the qualified authority input, historical27/88 remains explicit, PR23632/88 is
excluded, and this CR child contributes0. Global completion/error/budget/currency
remain null.

The assembly receipt records actual input/output pins and the metadata-only
scope. It is not a central-candidate review or publication receipt. Root must
then use the fresh actual central HEAD and this return/results pair with the
separate central builder, obtain independent review of that actual candidate,
and publish with expected-SHA/non-force semantics. No prior unit file, receipt,
source archive or publication state is modified by the assembler.
